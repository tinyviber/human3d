# Refinements

## 修连续性时不能只断言位置/速度连续，还要断言轨迹本身的物理形态 [1]

第一轮修复让离地帧继承接触点并强制零切线——位置、速度都连续了，但「A(地)→离地→C(地)」的路径贴地滑行。测试只查了"离开 A、速度非零"，没查"中途离地"。**教训：连续性测试通过不代表轨迹正确。断言要落在需求语义上（离地=高度 >0），不是代理指标上（速度 ≠0、不瞬移）。** 水平运动不能被认定为抬脚。

## 哈希与 ID 必须绑定真实数据内容，而非手工维护的版本号 [2]

`definitionSHA256` 哈希 `{id, revision}`，真实轨迹在 `authoring.ts` 的 `seq` 里——改关键帧不改 hash。`motionId` 只哈希请求体——换 rig/求解器后同请求同 ID 不同结果。**教训：可复现性声明的每一个输入都要进入哈希：真实定义、rig manifest、求解器版本。测试要写"改 X → hash 变"，而不是"hash 存在"。** 另外注意深拷贝：导出内部数据的函数若浅拷贝，调用方会污染模块状态。

## 事件按状态转换发射，不按状态采样发射 [3]

对每个 `plant=true` 关键帧发 `support-start`，持续支撑产生 N 个"开始"。**教训：语义事件映射到状态机的边（false→true / true→false），不是节点。** 起始即支撑也要算一次转换。下游做分段/接触重建时，区间语义（start/end 配对）比瞬时采样更有用。

## 测试必须走真实实现路径，拒绝旁路替身 [4]

三个实例：HTTP 冒烟用自建简化 server 而非真实 `serve.ts`（gzip 解压路径根本没被测到）；browser-qa 刷新后只读 localStorage（没验证内存文档与骨骼）；第一轮用"速度非零"代理"离地"。**教训：测试入口要尽量贴近真实边界——起真进程、查刷新后的内存态、断言求解后的骨骼位置。** Mock 测的是 mock 的行为。

## 算法支持的能力必须存在真实的 UI 写入路径，否则等于没有 [5]

插值器会消费 `foot.target.y` 作摆动路径点，但拖动被锁在水平面、面板无高度控件——功能在数据层存在、在交互层不存在。**教训：检查"端到端可写性"：参数能进文档吗？有控件吗？禁用态合理吗？** 评审关注的是用户能否完成工作流，不是字段是否存在。

## 显示值与可编辑值是不同实体时，必须拆成两个控件，拒绝"写成功但无反馈" [6]

离地帧时刻脚骨骼在接触点 A、可编辑目标是路径点 B，手柄绑 A 上写 B——鼠标动、手柄不动。**教训：当渲染位置 ≠ 编辑目标时，把它们拆成两个视觉实体（passive 显示柄 + 可拖动编辑柄），各自的拖动语义和视觉反馈保持一致。** 手柄必须跟手，这是所见即所得的底线。

## 对死数据写入给出显式用户提示 [7]

末尾离地帧没有后续区间，存储高度永远不会被采样——用户能写但写了没用。**教训：识别"可写但无效"的状态组合，在 UI 上就近提示（"此离地帧位于动作末尾，请先添加后续关键帧"），而不是静默接受。** 这比对每种异常加校验便宜且更诚实。

## 边界值协议用等式约定而不是近似约定 [8]

`round(duration*fps)+1` 网格假设 `duration*fps` 整数——`forehand@fps=1` 丢了 5.2s 终点。**教训：采样网格的终点语义写成显式契约（`timestamps.at(-1) === duration`），非整数网格追加精确终点而不是截断；独立校验器把契约变成硬检查。** "近似等于 duration"会让下游播放器丢最后姿态。

## 声明的契约必须实现；资源上限要同时切断 CPU 路径 [9]

文档声明支持 gzip 但服务端不解压——契约与实际行为漂移比没有该功能更糟（调用方按文档写代码必炸）。**教训一：README/OpenAPI 里每一条声明都要能找到实现与测试。** 其次，413 拒绝只停"保存数据"不停解压——**资源上限要同时切断内存路径和 CPU 路径（`stream.destroy()`），否则攻击者仍能用超限请求烧 CPU。**

## 修复引入新语义的测试盲区时，同步补一个该路径的端到端断言 [10]

第三轮只加了滑块测试，第四轮就被指出"没测 3D 拖动"——而 3D 拖动恰是 bug 所在路径。**教训：修交互 bug 时，测试要复现"出问题的具体交互路径"（真实指针事件、真实 input 事件），不能只测方便的旁路（直接改数据）。** 每轮新增能力都顺手配一条走真实路径的断言，下一轮 review 的盲区就少一块。
