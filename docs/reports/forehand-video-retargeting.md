# 正手视频重定向：根因、修复与框架边界

## 结论（2026-10-20 更新）

此前本报告的结论「IK 与播放路径无错、差异只来自缺少标定」只对了一半。h3d 的双骨 IK 确实把文档里的手腕目标送到了骨架，但 17 个球员正手预设里的**手腕 / 肘目标本身是错的**：生成器把未标定的 MediaPipe 2D 关键点直接混合进三维任务空间目标，目标落到肩正下方贴躯干的位置（肩—腕距仅 0.12–0.36 倍臂长），求解器只能把肘顶到 145° 屈曲钳位，球拍臂因此折进躯干。这是用户截图里所有网球动作「手臂极度折叠、球拍贴头贴身、手臂穿入躯干」的直接原因。

内置的 49 键 `forehand`（正手挥拍）是另一处独立缺陷：随挥段（约 3.1–4.2 s）手腕目标绕到身体左前方时，肘 pole 仍停在躯干后方，肘被求解到胸前并穿入躯干。该缺陷此前被标注为「已知未修复」。

两处都已修复，修复的是**动作数据与生成脚本**，没有改 `motion-core` 求解语义，因此没有 bump `SERVICE_VERSION`。

## 根因细节

生成器 `scripts/generate-player-forehands.mts` 旧版的关键点映射：

- `x` 被固定为 ±0.19 m，与求解后的肩位置无关；
- 归一化图像 `x`（像素/宽）与 `y`（像素/高）混用同一尺度，再把图像 `x` 一律当作世界 `z`；对正面 / 背面机位这把左右误当前后；
- 单目图像只观测到相机平面内的投影，把投影距离当三维距离必然缩短手臂；
- 混合权重取关键点置信度（≤0.95），因此种子动作里本来可达的目标几乎被整体替换。

修复前（HEAD）在真实回放路径 `frameAt → solveEffectiveFrame` 上采样 24 等分 + 全部键时刻、用生产蒙皮网格的 `PoseValidityChecker` 测得：

| 动作 | 持拍臂肘峰值 | 顶到 145° 钳位的帧 | 肩—腕最小可达比 | 手臂—躯干交叉帧 |
|---|---:|---:|---:|---:|
| novak-djokovic-forehand | 145° | 11 | 0.21 | 20 |
| daniil-medvedev-forehand | 145° | 6 | 0.23 | 13 |
| flavio-cobolli-forehand | 145° | 4 | 0.14 | 22 |
| jakub-mensik-forehand | 134° | 0 | 0.39 | 27 |
| alexander-bublik-forehand | 112° | 0 | 0.56 | 22 |
| forehand（内置 49 键） | 116° | 0 | 0.53 | 15 |

17 个预设中 9 个有钳位帧，全部 17 个都有手臂—躯干交叉（4–27 帧 / 29 帧）。

## 为什么不「修映射」而是「去掉映射」

曾实现一个修正版映射（以求解后肩为锚、保两段骨长、按肩宽比推断正 / 背 / 侧机位、枚举离面符号、置信度门限 0.6）。接入生成器后结果仍然不可用：多数球员出现 11–27 帧手臂—躯干交叉，部分仍顶到 145° 钳位，腕残差达 52 mm。原因是数据本身：合辑视频机位混合且未标定，五帧的左右手 / 帧选择不一致，深度不可观测。相比之下，只用工作台正手种子做参数化缩放：全部预设无钳位、可达比 0.64–0.73、残差 ≤34 mm，只剩 4 名球员恢复键有 1–2 帧轻微交叉。

按 KISS / YAGNI，生成器现在只保留它真正能兑现的部分：以 `spec/examples/forehand-study.request.json` 的正手种子为基础，按各球员参数（时序、髋 / 肩转动、幅度、站位、脚步、随挥高度）生成变体；视频关键帧秒数只作为 `videoTime` 来源说明。信封 `description` / `method` / `notes` 同步改为诚实描述，不再声称「肘腕目标来自 2D 关键点」。残余的恢复键交叉通过随挥 / 恢复键的肘 pole 前移 0.2 m（权重 `[0,0,.25,.75,1]`）消除。修正版映射模块已退役，不进入仓库。

## 第三代：以手捏正手为参考（2026-10-20 夜）

用户在工作台把 Novak 预设复制成「手捏正手」，只重捏了 **引拍1 / 引拍2 / 击球** 三键的手臂；其余键仍是上一代生成器的原样拷贝。这三键现在是唯一的手臂参考，已固化为 `scripts/forehand-arm-reference.json`（`authoredKeys` 明确列出，`inheritedNotice` 明确其余键不是参考）。内置 49 键 `forehand` 也被用户判定为错，**不再作为参考**。

手捏三键在求解后的躯干系里是什么形状（`scripts/lib/forehand-arms.mts` 的语言）：

| 键 | 持拍臂肘角 | 大臂仰角 | 拍轴（仰角/方位角） | 非持拍臂肘角 |
|---|---:|---:|---:|---:|
| 引拍1 | 34.8° | −19.9° | +56.5° / −2.7° | 113.5° |
| 引拍2 | 62.4° | −42.9° | +39.9° / −117.7° | 8.4° |
| 击球 | 47.9° | −23.2° | −8.4° / −104.8° | 8.4° |

即：**击球不是直臂**（肘 48°，拍面近乎水平指向体侧），落拍是 C 形最低点（大臂 −43°、拍头下坠），引拍时球拍立在肩侧。上一代生成器的「触球肘 < 30°、随挥折肘到 105°」的编舞与用户手捏形态不同，这是它看起来依旧不对的原因之一。

现在的传递方式：

1. `readReference` 在生产求解器上把三键读成**躯干系系数**（腕方向 + 可达比 + 肘铰链 + 拍轴），因此与躯干转角无关；
2. `placeRacketArm` / `placeOffArm` 只做**绕肩的均匀缩放**（`1+(reach−1)×0.35`，≤5%），绝不逐轴缩放世界坐标——逐轴缩放会把手臂剪切成上一代「扭曲」的样子；
3. 手帧的 `forward` 由**拍轴 + 前臂方向**导出，不自由存储，所以求解器 59.8° 腕锥按构造满足，存下来的轴就是渲染出来的轴；
4. 预设现在是 **9 键**：准备 → 引拍 → 落拍 → 前挥 → 击球 → 延伸 → 折肘 → 随挥 → 恢复。前挥是真实求解的中间键（落拍/击球躯干系系数按 35% 插值），因为三段「落拍→击球」跨度对最快转体的球员（Alcaraz / Tiafoe / Rune）太长：肘极点在**世界坐标**插值，躯干转动时直臂被拖过胸肌（3 名球员各 1 帧、最多 7 个三角相交）。加真实中间键 + 该段 linear 曲线后全部归零。
5. 非持拍臂的摆动键按 90% 可达放置（`OFF_REACH_SCALE`），只绕自己肩部均匀缩短、方向不变——手捏的腕方向保留，肘多弯一点，既消除腋下相交也不写出求解器够不到的目标。
6. 其余键的肘极点在过渡时先向外下摆再回位（`offTransition`），避免两端极点线性插值穿胸。

往返校验（`scripts/forehand-arms.test.ts`）：把三键读成系数再放回**同一躯干**，持拍腕、持拍肘、非持拍腕位移均 < 0.1 mm。

同时修掉的两处**脚/骨盆**语义拒绝（上一代 17 个预设里 7 个被服务端 422）：

- 每键 `rootStep` 曲线在 `击球` 支撑切换处把骨盆向前猛推，叠加踝背屈修正后根部加速度达 41–48 m/s²（门限 40）。删掉该曲线，步幅交给前脚目标；最差 48 → 26 m/s²。
- 前脚落地距离取摆动推进的 100% 时，落地后被当作支撑脚的接触点与求解需要的位置差 1.3–1.5 cm（门限 1 cm）。落地取 70%。

第三处脚/骨盆修正：`击球` 键的支撑切换曾把支撑脚锁在推进后的位置，重新落地时与求解需要的接触点差 1.3–1.5 cm；落地取摆动推进的 70%（`LAND_SCALE`）后滑移归零。

当前状态（`npx tsx scripts/measure-player-forehands.mts 24` + `scripts/workshop-capture.mjs` 逐帧渲染）：

| 腕锥钳位 | 0 帧 |

## 双臂编舞（2026-10-20 第二、三轮）

用户复查两次指出手臂形态不对：（1）持拍臂应从下往左斜上画 C，大小臂夹角先快速接近 180°（触球前后近直）再自然舒展随挥，不能锁死肘角；（2）非持拍臂引拍时应护在身前，随挥快到左肩时顺势在拍喉接住球拍，拍头接近竖直位于左肩上方。第一次按「左臂近直横伸指向来球」实现后被否，改为现方案。

实现集中在 `scripts/lib/forehand-arms.mts`（纯 TS，three 只作数学库，生成器与内置正手编辑脚本共用）。所有锚点都写在由求解后两肩定义的**躯干系**里（外侧 = 非持拍肩 − 持拍肩、上 = 世界 +Y、前 = 外侧 × 上，按握拍侧取号），因此手臂随躯干转动，左手持拍预设是右手的精确镜像：

- 持拍臂：`contact` 保留作者的触球方向、把肩—腕拉到 0.98 倍臂长（肘约 23°）；`sweep` 以肩为中心旋转近直臂到 `extend`（正前略上，拍头已抬起）；`fold` 在**链空间**插值到 `finish`（上臂/前臂方向各自 slerp、肘中段抬高走弧线）——用腕位置弦线插值会让双骨求解把上臂拉进胸肌，实测 18 → 0 交叉；`finish` 肘约 70–80°、手在非持拍肩前、拍轴距竖直 20–23°、拍头在该肩上方 0.45–0.56 m；`settle` 为定格稍收。肘 pole 一律放在「肩→预期肘」延长线上，使求解肘位与锚点一致。
- 非持拍臂：`guard` 肘外展约 80°、前臂横在胸前（肘必须外展：肘前收时准备→引拍插值会把上臂拖过胸肌，实测 11/41 采样交叉 → 0）；`tuck` 收到胸前；`catch` 手心贴向拍喉（腕沿拍轴 0.20 m 处，掌心偏移 0.08 m），`offReach` 过渡时肘 pole 先外下摆再回位。
- 内置 49 键正手按时间窗 smoothstep 混合（持拍臂 2.30→2.55 straighten、→2.85 sweep、→3.45 fold、持到 3.80、→4.60 回作者恢复；非持拍臂 0.60→1.20 guard、→2.30 持、→2.60 tuck、→3.40 catch、持到 3.90、→4.60 回）；球员预设在触球与随挥之间插入「延伸」「折肘」两个由同一编舞生成的路点键。

第四轮反馈：大臂不能只绕竖直轴转，肩要先把大臂带下去再斜向上。实测旧版预设大臂仰角在引拍→触球→定格全程停在 −45° 左右（只有方位角在变）。现在预设的引拍→触球由链空间路点键（摆步、落拍、前挥、近球）驱动：大臂仰角 −40° → −55°（落拍，肘外展、前臂近竖直、拍头在手下方）→ −14°（触球）→ +21°（定格，大臂高于肩线）；插值量是肩—腕弦向、肘铰链方向与肘角三者，而不是上臂/前臂方向各自 slerp——后者会让肘在两个弯曲锚点之间穿过伸直态、铰链方向在 50 ms 内翻 156°（上臂 100–120 rad/s，服务端拒绝）。落拍锚点的铰链与作者引拍/触球铰链的夹角控制在 35°/48°。内置 49 键正手的引拍→触球段保留作者 C 形（大臂 −12° → −54° → −43°，本身含下落），只在触球前伸直手臂。

踩过的坑：存储的手部目标是世界坐标（`handFrames: pelvis` 只决定键间插值系），第一轮把它当 pelvis 系换算导致目标落到 y≈0.44 m；`extend` 若带任何外侧分量（≥0.15）上臂即穿胸；左手拍轴 = −(forward × normal)（左侧挂载是右侧的 x 镜像，叉积变号），已用 `handAxis(hand, side)` 封装并对镜像 ready 文档验证为 0°。

## 框架边界与后续方向

要把同一机位下的动作做得接近视频，需要独立工具链，而不是把未标定的 2D 点塞进现有 IK：

1. 对每段视频估算相机内外参、人物尺度和地面平面，并让 h3d 用对应虚拟相机渲染；单目 2D 点不能单独解出肢体深度。
2. 在人体点之外检测球拍握柄、拍面和触球时刻；把握拍腕位置、肘 pole、前臂扭转和手掌朝向作为一组约束。
3. 从足踝 / 脚跟 / 脚尖轨迹检测支撑区间和落脚事件，再生成根位移及连续的摆动轨迹。
4. 任何任务空间目标写入前先做可达性校验（肩—腕距落在 `[minReach(145°), 臂长]`、肘 pole 在躯干外侧），并用 `measure-player-forehands.mts` 这类真实路径度量把关。
5. 五个关键姿态不足以重建快速网球挥拍；近似复刻需要更密集的逐帧追踪，并保留关节限位、接触区间和时间采样契约。

## 第四轮（2026-10-21）：下肢、基础动作、球拍插件与帧插入

### 下肢（17 个正手预设）

此前的下肢几乎静止：双脚不动、脚 pitch 为 0、骨盆仅下沉 2–5 cm。本轮按视频帧（准备、引拍、击球、随挥）给每位球员的骨盆和双脚加上可观察的动作，手臂不变：

- **屈膝与骨盆高度**：`LEG_ROOT_Y=[-1,-1.2,-.4,-.25,-.5] × crouch`，`crouch` 逐球员设置（0.03–0.11）。引拍最低、击球后升起、恢复时回落。
- **重心左右移**：`LEG_ROOT_X = [0,−1,.5,.5,.2] × WEIGHT_SHIFT`（`WEIGHT_SHIFT = 3.5 cm`）：引拍时骨盆偏向持拍侧脚 3.5 cm，落拍与前挥时偏向前脚 1.75 cm。
- **前向驱动**：骨盆前移 = `forward × travel + step × LEG_ROOT_STEP`。前脚（左脚，右手球员）在落拍时抬起、前挥时摆出，击球时落在前方；落脚前移取步长的 70%，避免支撑脚在骨盆修正下滑移。
- **后脚蹬转**：后脚（持拍侧）在前挥（第 3 键）时松开，脚跟微抬 4°；击球（第 4 键）时以脚尖朝网的 6° 偏航重新踩在脚掌上，脚跟抬起 **8°**；随挥（第 7 键）再次松开，脚跟抬起 4°；恢复（第 8 键）重新平放。
- **后踝背屈守卫**：修正后的解仍可能使后踝背屈超过 20°（工程门限）。`GUARD_TRIES` 按代价排序，依次尝试：自落拍起骨盆抬高 0–24 mm、随挥释放后脚跟再降 4°/8°、前脚摆动抬起减为 50%。每位球员采用第一个使背屈峰值 ≤ 20.05° 的方案；通过的动作保持原样。各预设选用的方案及其说明已写入资产 `notes`（“背屈校准：…”）。

**为何脚跟抬起是 8°，而不是 12°**：12° 时后踝背屈需求在 前挥→击球 之间过零，骨盆修正因 `max(0, 所需位移)` 产生斜率拐点。服务端默认 40 Hz 下 Frances 预设的根加速度为 42 m/s²，超过 40 的语义门限，`POST /v1/motions` 返回 422；240 fps 下该拐点高达约 90 m/s²。改为 8° 后，两种采样率下根加速度都明显低于门限。反向的约束：前挥时脚跟不抬（pitch 0°）根加速度仍超限；击球时脚跟抬到 4° 则后踝背屈限位饱和、脚滑移（support slip 422）。脚尖抬起的穿插则来自两键之间脚踝高度的线性插值：从 0° 到 20° 穿入地面约 24 mm，4°→12° 约 2.5 mm，现 4°→8° 为 0.0 mm。

### 基础动作库（5 个，≤3 关键帧）

`scripts/generate-basic-actions.mts` 生成 `assets/motions/basic-*.json`，信封 `category: 'basic'`，顺序 25–29：

### 动作库分组与插入到当前帧

- 动作库下拉分三组：**基础动作**、**网球正手（球拍插件）**、**其他预设**。默认选中“半蹲”。
- 手捏时，在关键帧按钮下方新增“基础动作 + 在当前帧插入”一行（`data-testid="basic-insert"`）。`insertBasicAction`（`apps/web/src/workshop/basic-actions.ts`）的行为：
  - 播放头在既有关键帧 0.01 s 内时复用该帧作为动作的第一帧，不产生重复时间戳；否则从当前姿态采样一个新关键帧。
  - 之后的关键帧 = 当前姿态 + 动作的相对偏移（根、躯干、双脚）。**手臂保持当前姿态不变**，不被动作覆盖。
  - 播放头之后的关键帧整体后移动作时长，动作时长随之增加（一次撤销即可回退）。
  - 动作移动的脚随动作的支撑标志，在最后一帧释放；动作不移动的脚保留当前接触，不会滑动或离地。
  - 超过关键帧数或 `maxDuration` 上限时拒绝，界面显示原因且文档不变。
- 浏览器验证（沙箱内 Playwright，开发服务器 `/workshop.html`）：默认选中“半蹲”，在 0.80 s 插入；提示“已在 0.80s 插入「半蹲」，后续关键帧后移 1.60s。”，时间轴出现 1.60 s 与 2.40 s 两个新帧，动作时长变为 2.40 s，控制台无错误。

### 限制（未解决）

- **手臂未按球员逐个调整**：手臂仍是用户手捏参考（引拍1 / 引拍2 / 击球）的躯干系模板，只做 ≤5% 的幅度缩放。单目视频的低分辨率参考无法可靠确定三维手臂目标。
- **屈膝深度仍浅于视频**：骨盆下降受后踝 20° 限位约束；全蹲与弓步的深度同样如此。
- **根加速度与采样率相关**：服务端 40 Hz 下正手最大 20.9 m/s²（Frances），240 fps 探针下最大 25.5 m/s²（Ben Shelton）。两者均低于门限，但拐点敏感，修改脚部参数须复测两种口径。
- **骨盆修正饱和**：240 fps 探针中，Roger 有 52 个采样处于骨盆修正饱和（HEAD 为 40），Marin 为 33（HEAD 为 20），Frances 为 29（HEAD 为 18）。饱和表示求解器报告所需修正未能满足可达性，不触发语义校验；这些帧留待视频对照。
- **支撑脚滑移**：左脚支撑段的最大漂移 8.6 mm（Frances，门限 10 mm）。
- **Felix 的 t465 参考帧**：该帧与其他帧不一致（误为 Valentin Vacherot），未做修正。
