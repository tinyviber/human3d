# 正手视频重定向：对照结果与修复方向

## 结论

当前检查没有证据表明 h3d 的双骨 IK 或工作台播放路径本身出错。它能将文档里的手腕目标送到骨架，Novak Djokovic 触球帧的实测腕目标与求解腕点重合，球拍握柄偏差为 0。已看到的差异来自把单目视频的二维关键点直接映射到三维骨架时缺少相机/深度标定，以及动作仅有五个关键姿态；这属于视频重定向能力缺口，尚不能归因为框架缺陷。

当前动作仍是近似，不应描述为接近逐帧复刻。腕部朝向、球拍平面方向和肢体深度没有从视频可靠恢复，脚步也只编码了少数摆动区间。相同视角的图像分数可以辅助定位偏差，但无纹理人体与真实运动员服装的检测置信度不同，分数不能证明三维动作等价。

## 轻量级外部对照工具

工具和模型保存在仓库外的 `/tmp/human3d-pose-debugger`，本地地址为 `http://127.0.0.1:8765/`。工具在浏览器里用同一个 MediaPipe Pose Landmarker Lite 分析源视频帧和 h3d 截图，叠加 2D 骨架并按肩髋长度归一化比较 16 个关节点。模型文件 5,777,746 字节（约 5.78 MB）；工具只在本机处理素材，没有加入 h3d 依赖、打包或运行路径。

同一工具也提取了这些预设的选定视频帧关键点，精简后存于 `scripts/player-forehand-landmarks.json`。仓库只保留运动点位数据，不保留视频帧或模型文件。模型能提供人体 2D 关节，不直接提供球拍姿态、可靠的单目深度或源相机参数。

- 新增 17 位球员的正手动作预设，保留各自的五个视频时间点和选用说明；重复画面优先采用较长、全身更清晰的一段。
- 手腕和肘位置由选定帧的 2D 模型点映射到现有双骨 IK 目标；带置信度的点低于阈值时不参与映射。脚踝、膝、髋仍用于检测和比较，但未标定的 2D 像素不直接映射为 3D 腿目标。
- 复核 Alcaraz 第 93 秒球拍手后，纠正了一个左右手镜像配置：球拍腕对应画面中的 `rightWrist`，该预设现按右手重定向。
- 加入躯干平移、单侧小步与摆动中点；另加一个合成摆动姿态，使离地脚能够抬趾，再维持 `plant` 接触区间契约。
- 预设说明现在明确标记为 2D 摄像机空间近似，不再把它描述成逐关节人工重建或三维动捕。

## 同模型截图对照

在球员动作触球关键帧，按源视频中可见的人体朝向选择相近的 h3d 视角，再与对应视频时间点比较。误差单位为肩髋中点距离；越低越接近。这个值只用于二维定位，视角差异本身也会影响分数。

|---|---:|---:|---|---:|---:|---:|
| Novak Djokovic | 6 s | 1.16 s | 45° | 0.294 | 0.570 | 0.374 |
| Roger Federer | 132 s | 1.13 s | 背面 | 0.444 | 0.320 | 0.261 |

## 框架修复建议

要把同一机位下的动作做得接近视频，需要增加一个离线或独立工具链，而不是改坏现有 IK：

1. 对每段视频估算相机内外参、人物尺度和地面平面，并让 h3d 用对应虚拟相机渲染；单目 2D 点不能单独解出肢体深度。
2. 在人体点之外，检测球拍握柄、拍面和触球时刻；把握拍腕的位置、肘部 pole、前臂扭转和手掌朝向作为一组约束。
3. 从足踝/脚跟/脚尖轨迹检测支撑区间和落脚事件，再生成根位移及连续的摆动轨迹；不可把所有帧都设成固定站姿。
4. 以关键点置信度给 3D 重定向加权，求解后仍用真实渲染截图经过同一个检测器验收；记录逐点误差与脚底接触，不只看汇总分。
5. 五个关键姿态不足以重建快速网球挥拍。达到近似复刻需要更密集的逐帧追踪，且要保留 h3d 现有的关节限位、接触区间和时间采样契约。

若以后改变 motion-core 求解器或采样语义，按项目规则 bump `SERVICE_VERSION` 并更新协议验证。本次只新增动作数据/映射脚本，没有改变求解语义，因此没有改 `SERVICE_VERSION`。
